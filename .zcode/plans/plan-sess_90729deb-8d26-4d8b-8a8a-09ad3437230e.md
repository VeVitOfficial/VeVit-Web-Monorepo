# Import sourcing katalogu do VeVit Store

## Context
Analýza `VeVit_sourcing_master_1260_2026-08-20.xlsx` (1 260 řádků, 338 unikátních modelů, 14 značek) a chat exportu ukázala plán e-shopu VeVit. Store modul ve vevit-web-app už existuje (pages, cart, checkout, Stripe, Packeta), ale **`store_products` v Supabase má 0 řádků** — katalog je prázdný. Cíl: naplnit store vyčištěným sourcing katalogem jako prohlédnutelný, ale neobjednatelný sortiment (aktivní + vyprodané), s odhadovanými cenami z benchmarků a novou sourcing taxonomií kategorií.

Rozhodnuto s uživatelem: vyčištěný katalog (~700 SKU) · is_active=true + stock=0 (checkout blokuje) · ceny odhad z USD benchmarků · nové kategorie navíc k 116 demo.

## Krok 0 — Ověřit reálné schéma hostované DB
`store-checkout-service.ts:281` dotazuje sloupce `sku, is_sellable, allow_backorder, currency`, které nejsou v repo `supabase/sql/store/schema.sql` — hostovaná DB je napřed před repem. Před generováním seedu ověřím sloupce přes MCP (`information_schema.columns` pro `store_products`, `store_categories`). Seed použije jen bezpečnou podmnožinu: `name, slug, description, short_desc, price, sale_price, type, stock, images, brand, category_id, is_active, featured`.

## Krok 1 — Importní skript `scripts/store-import-sourcing.mjs`
Nový Node skript (konvence jako `scripts/aifb-docs.mjs`), xlsx cesta jako argument. Přidá `exceljs` jako devDependency + npm script `"store:import"`.

Zpracování:
1. **Čištění:** varianty, které jsou čistě balicí režim (`standard, office pack, school pack, bulk, EU retail, B2B bulk, basic, business, single, international`), se sloučí — pokud má model i reálné spec-varianty (délka, wattáž, barva, kapacita), balicí řádkypadnou úplně; pokud jsou všechny varianty balicí, vznikne 1 base produkt. Reálné spec-varianty zůstávají jako samostatná SKU.
2. **Ceny:** `mid(benchmark USD) × 23 Kč × 1.3 (doprava/clo) × 1.4 (marže)` → zaokrouhlení na psychologickou cenu (…9 Kč), minimum 49 Kč. Řádky bez benchmarku → medián odhadů dané kategorie, fallback celkový medián. `sale_price` NULL.
3. **Texty:** `name` = „ZNAČKA Model (varianta)", `short_desc` = „Značka · kategorie", `description` = šablona česky + věta „Orientační cena — produkt zatím není skladem." (`price` je odhad). Bez obrázků (product-card má „VeVit" placeholder).
4. **Kategorie:** mapovací tabulka v skriptu — 4 nové top kategorie: **Škola a kancelář**, **Kancelářský nábytek**, **Auto-moto**, **Síťové prvky a úložiště** + podkategorie z 49 kategorií xlsx (slugify s diakritikou, hierarchie přes `parent_id` subselect na slug — stejný vzor jako demo seed v `schema.sql`). Elektroniku a Pet napojím do existujících top kategorií (`elektronika-a-prislusenstvi`, `chovatelske-potreby-pet-products`).
5. **SQL výstup:** `--write` generuje `supabase/sql/store/migrations/20261112XXXX_sourcing_catalog_up.sql` + `_down.sql` (konvence existujících migrací). Idempotentní: kategorie `ON CONFLICT (slug) DO NOTHING`, produkty `ON CONFLICT (slug) DO NOTHING`, produkty linkují kategorii subselectem na slug. Down maže explicitním seznamem slugů. Výchozí režim `--dry-run`: report na stdout (počty podle značky/kategorie, cenové statistiky, 10 ukázkových řádků, warningy na chybějící mapování).

## Krok 2 — Drobné vylepšení store UI
- `src/lib/store-data.ts`: přidat `getBrands()` (distinct `brand` z `store_products` přes existující `dataApi`).
- `src/app/store/catalog/page.tsx`: do formuláře filtrů přidat `<select name="brand">` (serverová podpora `filters.brand` už existuje v `getProducts` — `store-data.ts:56`). Pro 14 značek je to smysluplný filtr.

## Krok 3 — Aplikace na DB
Seed aplikovat přes Supabase MCP `apply_migration` (název `sourcing_catalog_seed`). Žádné destruktivní zásahy — vkládání nových řádků, demo kategorie i tabulky zůstávají nedotčené.

## Krok 4 — Verifikace
1. Dry-run report skriptu (počty, ceny, mapování kategorií — 0 warningů, nebo vysvětlitelné).
2. Po aplikaci: MCP `execute_sql` — počet produktů, distinct brandů, nových kategorií, kontrola duplicit slugů, `price` NOT NULL splněno.
3. `npm run dev` → projít `/cs/store` (homepage s featured), `/cs/store/catalog` (fulltext, kategorie, značka, řazení), detail produktu, pokus o checkout → musí skončit chybou „Požadované množství není skladem" (`store-checkout-service.ts:189`, fyzické zboží se stock=0).
4. `npm run lint` + rychlá kontrola TypeScript u změněných souborů.

## Poznámky / rizika
- Hostovaná DB má navíc sloupce oproti repu — krok 0 to vyjasní; seed se sloupcím vyhne.
- `store-data.ts` cachuje fetch 300 s s tagy — na Vercelu se katalog obnoví do 5 minut; lokálně v dev okamžitě-ish.
- Ceny jsou zástupné odhady (v description označeno „orientační"); re-run skriptu s novějším xlsx je bezpečný díky `ON CONFLICT DO NOTHING` (aktualizace cen později přes `DO UPDATE` variantu, až budou reálné nákupní ceny).
- Data xlsx zůstávají v `~/Downloads`; do repu se dostane jen vygenerovaný SQL seed (reprodukovatelné ze skriptu).
