# Fáze 3: GoPay (bankovní tlačítka, paysafecard) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zákazník Store může zaplatit bankovním tlačítkem české nebo slovenské banky nebo paysafecard přes GoPay.

**Architecture:** Server vytvoří platbu GoPay nad existující objednávkou a přesměruje zákazníka na bránu GoPay. Stav platby se vždy zjišťuje dotazem na GoPay API: po notifikaci i po návratu zákazníka. Zápis „zaplaceno“ sdílí jednu funkci se Stripe webhookem (zásoby, entitlements, úlohy po zaplacení).

**Tech Stack:** Next.js 16, TypeScript, GoPay REST API (OAuth2), Supabase PostgREST, Node 26 `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-20-platebni-brana-a-pokladna-design.md` (kap. 5.4, fáze 3). Navazuje na fáze 1 a 2.

## Global Constraints

- Platí Global Constraints fáze 1 a 2.
- GoPay jen pro Store a jednorázové platby; metody `BANK_ACCOUNT` a `PAYSAFECARD`. Žádné Twisto/Skip Pay, žádná GoPay karta.
- Notifikace GoPay nic nedokazuje; rozhoduje stav vrácený `GET /payments/payment/{id}`.
- Měna `CZK`, částka v haléřích (GoPay `amount` je v nejmenších jednotkách).
- Prostředí: sandbox `https://gw.sandbox.gopay.com/api`, ostrý `https://gate.gopay.cz/api` (z `GOPAY_API_URL`).

## Review Focus

1. Notifikace dorazí dřív než návrat zákazníka nebo dorazí víckrát → objednávka se zaplatí právě jednou (test v Task 2 na idempotenci přechodu).
2. Zákazník zavře okno GoPay nebo platba vyprší (`TIMEOUTED`, `CANCELED`) → objednávka `failed` a lze zaplatit znovu jinou metodou (test mapování v Task 1).
3. Částka nebo měna v GoPay nesouhlasí s objednávkou → `manual_review`, ne `paid` (test v Task 1).
4. Návrat ze GoPay se stavem stále `CREATED` (banka potvrzuje později) → stránka čeká a ukazuje „Čekáme na potvrzení banky“, zaplacení dorazí notifikací (ruční ověření v Task 3).
5. Výchozí banka předvybraná v kroku 2 neexistuje v GoPay seznamu → brána nabídne všechny banky (test v Task 1).

  - `mapGopayState(state: string): "paid" | "pending" | "failed" | "refunded"` (`PAID` → paid; `CREATED`, `PAYMENT_METHOD_CHOSEN`, `AUTHORIZED` → pending; `CANCELED`, `TIMEOUTED` → failed; `REFUNDED`, `PARTIALLY_REFUNDED` → refunded; neznámé → pending)

  - `gopayCreatePayment(body: Record<string, unknown>): Promise<{ id: number; gw_url: string; state: string }>`
  - `gopayGetPayment(id: number): Promise<{ id: number; state: string; amount: number; currency: string; order_number: string; additional_params?: Array<{ name: string; value: string }> }>`
  - `markOrderPaid(orderId: number, evidence: { provider: "stripe" | "gopay"; reference: string; manualReviewReason: string | null }, now: Date): Promise<void>` (CAS přechod, idempotentní: už `paid` → no-op; zařadí úlohy po zaplacení)
  - Migrace: `store_orders.gopay_payment_id bigint unique`, tabulka `store_gopay_notifications(id bigserial, gopay_payment_id bigint not null, received_at timestamptz default now(), state varchar(32), result varchar(48))`
  - `POST /store/api/gopay-create.php` `{ order: string, instrument: GopayInstrument, swift: string | null }` → `200 { gw_url }`; přechod `pending_checkout|failed → awaiting_payment`, `payment_provider = 'gopay'`
  - `GET /store/api/gopay-notify.php?id=<id>` → vždy `200` (GoPay opakuje při jiném kódu), zpracování: `gopayGetPayment` → `gopayMismatch` → `markOrderPaid` / `failed` / `manual_review`, zápis do `store_gopay_notifications`
  - `POST /store/api/gopay-sync.php` `{ order }` → stejné zpracování na žádost stránky po návratu; odpověď `{ payment_status }`
